This directory introduces RouteWise's Supabase SQL migrations. No previous database
migration system was present. The migration is not applied automatically by Next.js.
No Supabase CLI configuration/project link or database credentials are committed.

Apply `migrations/20261014000000_create_user_preferences.sql` once to your intended
Supabase project using Dashboard > SQL Editor. Run the whole file; it is transactional
and deliberately fails if the table already exists rather than hiding schema drift.

Alternatively, with the Supabase CLI installed, from the RouteWise root:

```powershell
supabase init
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase db push --dry-run
supabase db push
```

If the remote project already has migration history, reconcile it with `supabase db
pull` before pushing. Inspect every pending migration in the dry run. Do not push
unreviewed unrelated changes. Use CLI credential prompts; do not put database
passwords or service-role keys in frontend variables. If you applied the SQL in the
Dashboard, do not run it again through db push; reconcile migration history first.

Schema: `public.user_preferences`

| Column | Type / behavior |
| --- | --- |
| user_id | UUID primary key, FK to auth.users(id), defaults to auth.uid(), deletes with account |
| preferred_transport_mode | Required text, one of PUBLIC_TRANSIT / DRIVING / WALKING / RIDESHARE; no inferred default |
| max_walking_minutes | Optional integer >= 0; NULL means no saved limit |
| max_budget | Optional numeric(10,2), USD, 0 to 99,999,999.99; NULL means no saved budget; non-finite/negative values rejected |
| route_priority | Required BEST / FASTEST / CHEAPEST; defaults to BEST |
| created_at | Required timestamptz, generated by database on insert |
| updated_at | Required timestamptz, generated by database on insert and update |

The primary key ensures at most one row per authenticated user and is also the index
for owner lookups. There is no signup trigger, initial data, saved-places table or
application integration. Preferences can be created when a future Save action exists.

Security:

- RLS SELECT: authenticated users can see only rows where auth.uid() = user_id.
- RLS INSERT: authenticated users can create only their own row.
- RLS UPDATE: both the old and resulting row must belong to the caller.
- Grants allow authenticated SELECT and INSERT/UPDATE of preference fields only.
  user_id may be provided on INSERT but cannot be updated. Timestamps cannot be
  supplied by browser writes. The trigger also preserves created_at and ownership.
- No anon/PUBLIC privileges, DELETE grant or DELETE policy. Users cannot delete rows
  in this stage. Auth-account deletion cascades through the foreign key.
- The timestamp function is security invoker with a fixed empty search_path and no
  direct browser execute grant. No security-definer bypass is introduced.
- Administrative database roles may bypass RLS, as usual; use normal user JWTs for
  future browser reads/writes, never service-role credentials.

The migration enables RLS itself; no additional Dashboard policy toggles or Auth
settings are required. If your project's Data API schema exposure differs from the
default public schema, review it before future frontend integration. No frontend
types or behavior change in this stage, so frontend checks are not required here.

Local validation (no hosted database connection):

```powershell
npm install --prefix .next/preferences-validation --no-save --no-package-lock @electric-sql/pglite
node supabase/tests/user_preferences.test.mjs
```

This installs a test-only embedded PostgreSQL engine into the ignored build directory,
without changing RouteWise dependencies. The test creates local stand-ins for the
Supabase Auth table/roles and validates the actual SQL, constraints, RLS allow/deny
behavior, timestamps and account-delete cascade. It is not a live Supabase integration
test. A Next.js build may remove the temporary engine; reinstall it to rerun.

References: [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)
and [user-owned data](https://supabase.com/docs/guides/auth/managing-user-data).
