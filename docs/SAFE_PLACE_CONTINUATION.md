# Safe Place continuation

After Route Me Here starts the temporary walking leg, the selected Safe Place panel includes Continue to your destination. The local context retains the first-leg origin, original final destination, selected Safe Place, started flag and selected continuation route ID/mode.

The user chooses an existing physically valid non-rideshare route/mode and clicks Start continuation. The handoff has STRANDED_RESUME context. The origin is a successfully refreshed device location, or the selected Safe Place when refresh has not succeeded. The original destination never changes. Transit alternatives retain their own IDs; genuinely unavailable routes are excluded. Main route details, pricing and geometry are historical plan data and are not rewritten or presented as newly calculated from the Safe Place. Maps calculates the remaining trip externally.

Refresh current location is explicit and uses an uncached geolocation request with a timeout. Failed/invalid locations fall back to the Safe Place. Start is disabled during the refresh so Maps can be opened synchronously on the subsequent user click. Stale refresh callbacks are ignored when the panel is unmounted or a different Safe Place is selected. There is no arrival detector or background GPS polling.

Clear Safe Place leg removes the local continuation and selection and invalidates pending inline-route work. Back to destination unmounts the Safe Place results; submitting a new trip creates fresh state. Exiting Stranded Mode or the app's Start Over also unmounts that local state. Nothing is written to account preferences or global trip history. Returning from Maps to the still-open RouteWise tab retains the selection; a full page reload does not persist this local state.

## Manual verification

While continuation is active, the main Stranded rideshare section receives pickup/dropoff from the same local context. Pickup uses a validated refreshed GPS point (accuracy at most 100 metres) or the exact Safe Place point/name. Existing current-location naming resolves readable GPS labels without changing the coordinate. Dropoff always uses the retained original destination. Uber and the existing Lyft link builder receive the updated endpoints; Waymo does not accept invented endpoint parameters and asks the user to enter them in its app. Existing Waymo coverage logic rechecks the new coordinate pair and can disable a previously available option; it does not promote previously unavailable results. Original displayed ride estimates are explicitly described as original-trip estimates, not updated provider quotes. Clearing/back/new-trip behavior also removes the rideshare endpoint override.

On Android/iPhone, start a Safe Place leg and return to the same RouteWise tab. Confirm the Safe Place and original destination remain visible. Start continuation without refreshing and inspect the Safe Place origin. Then explicitly refresh location and repeat, checking the refreshed origin. Deny location access and confirm the fallback. Switch transit/walking and verify the final destination and transit notice. Clear the leg, use Back to destination, exit Stranded Mode and start a new trip; confirm no old continuation is attached. No ride or arrival detection should start automatically.
